# R Project Scaffold

You are scaffolding a new non-Shiny R project. This skill defines the canonical project structure, dependency management conventions, and configuration that your R projects (non-Shiny, non-package) should follow.

## Activation

Activate when the user wants to create a new R project or needs to verify/fix an existing project's structure against the canonical layout.

## Inputs

- **Required**: project name (used for `.Rproj` file and DESCRIPTION `Package` field)
- **Optional**: whether this is a targets pipeline project (adds `_targets.R` scaffold)
- **Optional**: whether database connectivity is needed (adds DBI/pool to DESCRIPTION)
- **Optional**: reference project layout to mirror, if one already exists in this workflow

## Steps

### 1. Create the canonical directory layout

```
<project-name>/
├── .github/                   # GitHub configuration
│   ├── workflows/             # CI/CD workflows
│   └── PULL_REQUEST_TEMPLATE.md
├── R/                         # R source code
│   ├── functions/             # Reusable function files
│   └── scripts/               # Procedural scripts (numbered if ordered)
├── data-raw/                  # Raw source data (gitignored if sensitive)
├── data/                      # Processed/output data (gitignored if large)
├── docs/                      # Documentation
├── tests/                     # Test suite
│   ├── testthat/              # testthat test files
│   └── testthat.R             # Test runner
├── .Rproj                     # RStudio project file
├── .gitignore                 # R-specific gitignore
├── .lintr                     # lintr configuration
├── DESCRIPTION                # Package metadata (used for dependency declaration)
├── NAMESPACE                  # Namespace file (can be minimal for non-packages)
├── README.md                  # Project README
└── renv.lock                  # Dependency lockfile (generated by renv::snapshot())
```

If this is a **targets pipeline project**, also add:

```
├── _targets.R                 # Pipeline definition
├── _targets/                  # Pipeline cache (gitignored)
├── R/
│   └── functions/             # Target function definitions
```

### 2. Initialize renv

```r
# In a fresh R session within the project directory:
renv::init(bare = TRUE)  # Initialize without scanning for dependencies
# Then install packages explicitly and snapshot:
renv::install(c("testthat", "lintr", "styler"))
renv::snapshot()
```

**renv conventions:**
- Always commit `renv.lock` to version control
- Commit `renv/activate.R` and `renv/.gitignore`
- Never commit `renv/library/` (gitignored by default)
- Use `renv::restore()` as the first step for new contributors

### 3. Create the .Rproj file

```
Version: 1.0

RestoreWorkspace: No
SaveWorkspace: No
AlwaysSaveHistory: No

EnableCodeIndexing: Yes
UseSpacesForTab: Yes
NumSpacesForTab: 2
Encoding: UTF-8

AutoAppendNewline: Yes
StripTrailingWhitespace: Yes
LineEndingConversion: Posix
```

### 4. Create the DESCRIPTION file

```
Package: <project-name>
Title: <One Line Title>
Version: 0.0.1
Authors@R:
    person("First", "Last", email = "first.last@example.com", role = c("aut", "cre"))
Description: <One paragraph describing what this project does.>
License: file LICENSE
Encoding: UTF-8
Imports:
Suggests:
    testthat (>= 3.0.0),
    lintr,
    styler
Config/testthat/edition: 3
```

**Rules:**
- `Imports:` — packages required for the project to function
- `Suggests:` — packages needed only for development (testing, linting, styling)
- Use `package::function()` syntax in code; never use `library()` in function files

### 5. Create the .gitignore

```gitignore
# R artifacts
.Rhistory
.Rdata
.RData
*.Rproj.user
.httr-oauth

# renv
renv/library/
renv/staging/
renv/sandbox/

# Data (adjust per project)
data-raw/*.csv
data-raw/*.xlsx
data/*.rds
data/*.parquet

# targets pipeline cache
_targets/

# OS files
.DS_Store
Thumbs.db

# Environment
.Renviron
.env
```

### 6. Create the .lintr file

Follow `_partials/lintr-config.md` (`${CLAUDE_SKILL_DIR}/../_partials/lintr-config.md`)
for the canonical `.lintr` block — see `r-code-style` for the full linter
reference.

### 7. Verify the scaffold

After creating all files:
1. Open the `.Rproj` file in RStudio (or `cd` into the directory)
2. Run `renv::restore()` — should complete without errors
3. Run `testthat::test_dir("tests/testthat/")` — should pass (no tests yet is OK)
4. Run `lintr::lint_dir("R/")` — should return no findings on an empty project

## Outputs

- A complete project directory matching the canonical layout
- Initialized renv with lockfile
- Ready-to-use test infrastructure
- Clean lintr configuration

## Success criteria

- Running `renv::restore()` in the new project succeeds
- The `.Rproj` opens cleanly in RStudio
- `lintr::lint_dir("R/")` produces zero findings on the scaffolded code
- The directory layout matches the canonical structure defined in Step 1
- DESCRIPTION file is parseable by `desc::desc()`

## Out of scope

- Shiny-specific structure (www/, mod_*, launch_app.R) — not covered by this suite
- CRAN package structure (vignettes/, inst/, data/) → `r-package-structure`
- CI/CD pipeline setup → `r-ci`
- Pipeline definition (targets) → `r-pipeline-patterns` (this skill only creates the stub)
