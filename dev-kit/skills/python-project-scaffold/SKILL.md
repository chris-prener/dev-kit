# Python Project Scaffold

You are scaffolding a new Python project. This skill defines the canonical project structure, dependency management conventions, and configuration that your Python projects (scripts, tools, non-published packages) should follow.

## Activation

Activate when the user wants to create a new Python project or needs to verify/fix an existing project's structure against the canonical layout.

## Inputs

- **Required**: project name (used for the `src/<project_name>/` package directory and `pyproject.toml` `name` field)
- **Optional**: whether this is a Prefect pipeline project (adds a `flows/` scaffold)
- **Optional**: whether database connectivity is needed (adds sqlalchemy/duckdb to dependencies)
- **Optional**: reference project layout to mirror, if one already exists in this workflow

## Steps

### 1. Create the canonical directory layout

```
<project-name>/
├── .github/                   # GitHub configuration
│   ├── workflows/             # CI/CD workflows
│   └── PULL_REQUEST_TEMPLATE.md
├── src/
│   └── <project_name>/        # Importable package (underscores, not hyphens)
│       ├── __init__.py
│       └── py.typed           # Marks package as typed (PEP 561)
├── data-raw/                  # Raw source data (gitignored if sensitive)
├── data/                      # Processed/output data (gitignored if large)
├── docs/                      # Documentation
├── tests/                     # Test suite (mirrors src/ layout)
│   ├── conftest.py            # Shared fixtures
│   └── test_*.py
├── .gitignore                 # Python-specific gitignore
├── .python-version            # Pinned interpreter version (read by uv)
├── pyproject.toml             # Project metadata, dependencies, tool config
├── uv.lock                    # Dependency lockfile (generated by `uv lock`)
└── README.md                  # Project README
```

If this is a **Prefect pipeline project**, also add:

```
├── src/<project_name>/
│   └── flows/                 # Flow and task definitions
│       ├── __init__.py
│       └── main_flow.py
```

### 2. Initialize uv

```bash
# In the project directory:
uv init --package --name <project-name>
uv python pin 3.12          # Pin the interpreter version
uv add --dev pytest pytest-cov ruff mypy
uv lock
```

**uv conventions:**
- Always commit `uv.lock` to version control
- Commit `.python-version`
- Never commit `.venv/` (gitignored by default)
- Use `uv sync` as the first step for new contributors

### 3. Create the pyproject.toml

```toml
[project]
name = "<project-name>"
version = "0.0.1"
description = "<One paragraph describing what this project does.>"
readme = "README.md"
requires-python = ">=3.12"
authors = [
    { name = "First Last", email = "first.last@example.com" },
]
dependencies = []

[dependency-groups]
dev = [
    "pytest>=8.0",
    "pytest-cov>=5.0",
    "ruff>=0.6",
    "mypy>=1.11",
]

[build-system]
requires = ["hatchling"]
build-backend = "hatchling.build"

[tool.hatch.build.targets.wheel]
packages = ["src/<project_name>"]
```

**Rules:**
- `dependencies` — packages required at runtime
- `dependency-groups.dev` — dev-only packages (testing, linting, type-checking)
- Use `>=` minimum bounds for runtime deps; let `uv.lock` pin exact versions

### 4. Create the .gitignore

```gitignore
# Python artifacts
__pycache__/
*.py[cod]
*.egg-info/
.eggs/
build/
dist/

# uv / venv
.venv/

# Type checkers / test caches
.mypy_cache/
.ruff_cache/
.pytest_cache/
.coverage
htmlcov/

# Data (adjust per project)
data-raw/*.csv
data-raw/*.xlsx
data/*.parquet

# OS files
.DS_Store
Thumbs.db

# Environment
.env
```

### 5. Create the ruff + mypy configuration

Follow `_partials/ruff-config.md` (`${CLAUDE_SKILL_DIR}/../_partials/ruff-config.md`)
for the canonical `[tool.ruff]` block — see `python-code-style` for the full
ruleset. Add it to `pyproject.toml` alongside the mypy and pytest config:

```toml
[tool.mypy]
python_version = "3.12"
strict = true
files = ["src"]

[tool.pytest.ini_options]
testpaths = ["tests"]
addopts = "--cov=src --cov-report=term-missing"
```

### 6. Verify the scaffold

After creating all files:
1. Run `uv sync` — should complete without errors
2. Run `uv run pytest` — should pass (no tests yet is OK)
3. Run `uv run ruff check .` — should return no findings on an empty project
4. Run `uv run mypy src` — should return no findings

## Outputs

- A complete project directory matching the canonical layout
- Initialized uv environment with lockfile
- Ready-to-use test infrastructure
- Clean ruff/mypy configuration

## Success criteria

- Running `uv sync` in the new project succeeds
- `uv run ruff check .` produces zero findings on the scaffolded code
- The directory layout matches the canonical structure defined in Step 1
- `pyproject.toml` is parseable and has no missing required fields
