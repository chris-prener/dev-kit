# Python Testing

You are working with the test suite for a Python project. This skill defines the testing framework, test organization, naming conventions, coverage expectations, and patterns for writing effective tests in Python.

## Activation

Activate when the user needs to create tests, configure the test framework, verify test coverage, or understand testing conventions for a Python project.

## Inputs

- **Required**: what to test (function, module, data pipeline, etc.)
- **Optional**: existing code to generate tests for
- **Optional**: specific edge cases to cover
- **Optional**: desired coverage threshold

## Steps

### 1. Testing framework

| Layer | Framework | Purpose |
|---|---|---|
| Unit tests | `pytest` | Individual functions, pure logic, transformations |
| Integration tests | `pytest` (marked `@pytest.mark.integration`) | Multi-function workflows, pipeline stages |
| Snapshot tests | `syrupy` | Output stability for reports, complex objects |

**Config:** Declare in `pyproject.toml`:
```toml
[tool.pytest.ini_options]
testpaths = ["tests"]
addopts = "--cov=src --cov-report=term-missing --strict-markers"
markers = [
    "integration: marks tests that hit external systems (deselect with '-m \"not integration\"')",
]
```

### 2. Test directory structure

```
tests/
├── conftest.py                     # Shared fixtures (auto-discovered)
├── test_utils_data.py              # Tests for src/mypackage/utils_data.py
├── test_utils_formatting.py        # Tests for src/mypackage/utils_formatting.py
├── test_pipeline_ingest.py         # Tests for pipeline ingestion stage
├── test_pipeline_transform.py      # Tests for pipeline transformation stage
├── __snapshots__/                  # Snapshot output directory (auto-generated by syrupy)
└── fixtures/                       # Test data fixtures
    ├── sample_input.csv
    └── expected_output.parquet
```

### 3. File naming convention

| Source file | Test file |
|---|---|
| `src/mypackage/utils_data.py` | `tests/test_utils_data.py` |
| `src/mypackage/transform_orders.py` | `tests/test_transform_orders.py` |
| `src/mypackage/flows/ingest.py` | `tests/test_pipeline_ingest.py` |

**Rule:** Test file name = `test_` + source file name. Test function name = `test_` + behavior under test.

### 4. Test structure patterns

#### Basic unit test

```python
def test_clean_names_converts_to_snake_case():
    input_df = pl.DataFrame({"First Name": ["A"], "Last.Name": ["B"]})
    result = clean_names(input_df)

    assert result.columns == ["first_name", "last_name"]
```

#### Parametrized tests

```python
import pytest

@pytest.mark.parametrize(
    ("raw_input", "expected"),
    [
        ("2024-01-15", date(2024, 1, 15)),
        ("01/15/2024", date(2024, 1, 15)),
        ("15-Jan-2024", date(2024, 1, 15)),
    ],
    ids=["iso", "us-slash", "day-month-name"],
)
def test_parse_date_flexible_handles_multiple_formats(raw_input: str, expected: date):
    assert parse_date_flexible(raw_input) == expected
```

#### Testing exceptions

```python
def test_calculate_order_total_raises_on_negative_price():
    with pytest.raises(ValueError, match="must be positive"):
        calculate_order_total(unit_price=-1, quantity=3)
```

#### Snapshot tests for complex output

```python
def test_summary_table_matches_snapshot(snapshot):
    data = pl.read_parquet("tests/fixtures/sample_data.parquet")
    result = generate_summary_table(data)

    assert result.to_dict() == snapshot
```

### 5. Fixtures

#### conftest.py — shared fixtures

```python
# tests/conftest.py
import polars as pl
import pytest


@pytest.fixture
def sample_orders() -> pl.DataFrame:
    """A minimal, synthetic order dataset for tests."""
    return pl.DataFrame({
        "order_id": range(1, 11),
        "amount": [round(x, 2) for x in [19.99, 5.5, 500.0] * 3 + [42.0]],
        "status": ["pending", "shipped", "delivered"] * 3 + ["cancelled"],
    })


@pytest.fixture
def tmp_data_dir(tmp_path: Path) -> Path:
    """A temporary directory for filesystem-touching tests."""
    data_dir = tmp_path / "data"
    data_dir.mkdir()
    return data_dir
```

**Rules:**
- Use built-in `tmp_path` instead of manually managing temp directories
- Use `monkeypatch` for env vars and attribute patching — never mutate global state directly
- Scope fixtures (`scope="session"`) only for genuinely expensive, read-only setup

#### fixtures/ — static test data

- Store small, representative datasets as `.parquet` or `.csv`
- Reference via `Path(__file__).parent / "fixtures" / "filename.parquet"`
- Never use production data in fixtures — create synthetic data
- Keep fixtures small (< 1 MB each)

### 6. Coverage requirements

| Metric | Threshold | Enforcement |
|---|---|---|
| Line coverage | ≥ 80% | CI gate (warning below, fail below 60%) |
| Function coverage | 100% public functions | Every public function has at least one test |
| Branch coverage | Best-effort | Not gated but reviewed in PRs |

**Running coverage:**
```bash
uv run pytest --cov=src --cov-report=term-missing

# Generate HTML report:
uv run pytest --cov=src --cov-report=html
```

### 7. Testing conventions

**DO:**
- Test one behavior per test function
- Use descriptive test names: `test_<function>_<condition>_<expected>`
- Use `pytest.raises` to test error paths, with `match=` for the message
- Use `pytest.mark.parametrize` instead of loops inside a test
- Mock external calls with `unittest.mock` or `pytest-mock`'s `mocker` fixture
- Use `pytest.mark.integration` for tests that hit real external systems, and exclude them from the default run

**DON'T:**
- Don't test internal implementation details — test behavior
- Don't write tests that depend on execution order
- Don't use `os.chdir()` — use `tmp_path` and pass paths explicitly
- Don't hardcode absolute file paths — use `Path(__file__).parent`
- Don't leave `breakpoint()` calls in test code
- Don't mock what you don't own without a contract test verifying the mock matches reality

### 8. Running tests

```bash
# Run all tests:
uv run pytest

# Run a specific test file:
uv run pytest tests/test_utils_data.py

# Run a specific test:
uv run pytest tests/test_utils_data.py::test_clean_names_converts_to_snake_case

# Exclude integration tests:
uv run pytest -m "not integration"

# Verbose, stop on first failure:
uv run pytest -v -x
```

## Outputs

- Test files following the naming convention
- Properly structured test directory
- Coverage report (when requested)

## Success criteria

- All test files follow the `test_*.py` naming convention
- Each test function tests one behavior
- Coverage meets the 80% line-coverage threshold
- Tests run independently (no order dependence) and pass with `pytest -p no:randomly` disabled or enabled
- `uv run pytest` passes cleanly
