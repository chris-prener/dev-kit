# Contributing to {{PROJECT_NAME}}

Thanks for your interest in this project. Before filing an issue or opening a pull request, there are a few places to explore and pieces to put together to make the process as smooth as possible.

## Getting Started

If it's a bug or a feature request, you're in the right place — file an issue. If you're not sure, use the _other inquiry_ template and we'll help sort it out.

## Before Opening an Issue

Before opening a new issue, be sure to [search issues and pull requests][issuesLink] to make sure the bug or suggestion hasn't already been reported. If there is an existing issue and you want to express support for it, comment there instead of opening a duplicate.

By default, the search will be pre-populated with `is:issue is:open`. You can [edit the qualifiers](https://help.github.com/articles/searching-issues-and-pull-requests/) (e.g. `is:pr`, `is:closed`) as needed — for example, remove `is:open` to search all issues, open or closed.

## Issue Templates

When you go to open an issue, you are encouraged to select from one of the available templates: bug report, feature request, tech debt, documentation, or other inquiry. These help you craft an issue that's as helpful and clear as possible, and route it to the right label automatically.

## PR process

If you've found a way to contribute, follow the process below to fork, edit, and push your proposed changes. We recommend opening an issue first to gauge interest before spending time on a PR.

### Fork, clone, branch

[Fork][repoLink] the repository and clone it locally. Create a branch for each PR.

### Style

Match the existing code and documentation style. Be careful to only make style changes to the code you are contributing.

### Document

Update relevant documentation if your changes affect it.

### Commit

Write a clear commit message describing what you've done. If you've fixed or closed an issue, include a keyword (e.g. `fixes #101`) at the end of your commit message (not in its title) to automatically close the issue when the PR is merged.

### Push and pull

Once you've pushed your commit(s) to a branch in your fork, open the pull request. Give it a descriptive title, and reference any related issue by number (e.g. `#15`) in the description.

## Code of Conduct

Please note that this project is released with a [Contributor Code of Conduct](CODE_OF_CONDUCT.md). By participating in this project you agree to abide by its terms.
